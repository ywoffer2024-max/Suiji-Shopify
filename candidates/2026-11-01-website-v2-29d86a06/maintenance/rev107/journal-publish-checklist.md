# Journal publication and maintenance checks

For the existing English/French SUIJI Journal. Reuse the native Article identity and the approved source; this checklist does not authorize deleting articles, changing tracking, or inventing product facts.

Before each publication:

1. Confirm one consumer question, an early useful answer, practical checks, limitations, sources and one main next action. Retain the full approved English and French bodies and Rowan byline.
2. Keep one visible H1. Body sections begin at H2; comparisons use actual text/tables. Remove accidental pasted editor styles without deleting meaningful content.
3. Keep a deliberate list excerpt and native SEO title/description. Do not prepend the same excerpt to a detail body that already contains its introduction. Character counts are review aids, not ranking guarantees.
4. Use a feature image only when its subject and source are approved. Jewelry images must be matched final2 white images; do not attach an unrelated product to satisfy a checkbox. Check localized alt text, intrinsic dimensions, responsive size and actual visual output. No invented image or test claim.
5. Preserve existing handles. A necessary URL move needs an explicit old-to-relevant-new redirect plan, approval within task scope and actual old-link readback. Do not rename working articles merely to shorten a slug.
6. Check the real canonical and Shopify Markets language alternatives. Native Journal tag archives repeat the guide list and use noindex,follow; normal Journal/Article eligibility is unchanged. Do not replace managed robots rules or add a sitemap App as a shortcut.
7. Confirm a visible Home / Journal / article breadcrumb and matching BreadcrumbList; one BlogPosting with actual author, canonical, language and timezone-qualified publication date. A reviewed date and dateModified require the same real, typed suiji.content_reviewed_at field; leave both absent otherwise.
8. Keep deterministic, same-topic related reading: up to two other approved guides, excluding the current article. One is correct when that topic has only one other guide. Check links from relevant product/system pages back to guides and from guides to a suitable next step.
9. Do not load video players or unrelated Apps by default. Keep tables scrollable within their region, deferred secondary media and the existing script-loading boundary. Check the article template itself on mobile and desktop.
10. Internal links carry no campaign UTM parameters. The data-journal-link attribute is a measurement hook; it does not certify that an analytics event was installed or collected. Keep the existing single Google integration and consent handling. Preview actions are never purchase events.
11. Keep comments disabled unless someone owns moderation. Preserve native Markets/Translate & Adapt and deliberate language/country selection; do not add IP-based forced redirects.

Before release:

- Run portable generation and the design contract checker; capture official Theme Check output and distinguish inactive-language baseline errors from new code or active EN/FR errors.
- Check current shared templates in English and French at desktop/mobile widths, including narrow reflow. Verify full body preservation, links, local selection isolation and custom-work final-sale notices.
- Freeze exact source/theme hashes. The sole Store writer backs up and applies only the reviewed delta, then reads back the actual theme, native content and translations. Keep a rollback payload. The sole Git writer independently backs up the same source.
- Recheck actual published HTML: one H1, canonical/alternate metadata, structured-data JSON, breadcrumb, dates, related links and image provenance. A local pass does not certify native Shopify output, physical devices, Core Web Vitals or indexing.

After release:

- Use GSC page filters for article paths, for example /blogs/journal/<handle>, excluding tag/list pages. Record the actual date range and market/language. A sitemap entry, an HTTP200 page and an indexed result are separate checks; keep any known native XML completeness limitation explicit.
- Separate search impressions/clicks, AI-feature impressions, referral visits and real order outcomes. The Google Generative AI performance report has its own eligibility/data threshold; do not infer the account has data because the report exists. GA4 campaign changes do not automatically start a new session.
- Periodically review broken/orphan links, consumer usefulness and sufficiently long performance history. Update a useful article before considering consolidation. New or zero-click content is not automatically worthless; do not bulk-delete or hide it without evidence and a URL plan.
- Repeat native HTML, structured-data and representative performance checks after theme/App changes. Preserve independent before/after evidence and avoid adding a second analytics installation.
