# PRD — SUIJI AI 花饰共创与底托搭配

版本：v0.2 · 2026-10-31 · 状态：加入顾客端边界、AI 自动可做审批、设计师与邮件流程

本文件是内部产品需求，供团队实施；实际网站功能只展示与顾客设计相关的界面。

本版配套：[顾客页面与流程](customer-experience-v0.2.md)、[审核与邮件规则](review-and-email-v0.2-final.md)。前期[方法/Skill 调研及工厂模板](https://github.com/ywoffer2024-max/Suiji-Shopify/tree/0423248279eb5ec43bb280ab7dfba4ccff1d26ea/research/2026-10-31-ai-charm-prd-v0.1-7de2b129)保留为已固定来源。

## 1. 概要

在 SUIJI 网站增加花饰共创页面，让用户用文字、参考图和可选项表达想法，生成设计方案，再与真实底托搭配预览。**最终目标是可准确制作的首饰：通过 CAD、工艺与实物验证后，交付工厂认可的 STL/3MF 打印文件及工程资料。**

首版把可变花饰和固定底托接口分开管理，支持树脂打样与直接金属打印。顾客提交后先由 AI 审核；简单且处于已验证工艺/结构范围内的设计，可自动通过制作可行性审批。无法自动通过、较复杂或通过后发现问题的方案转交设计师，由邮件沟通并确认需求。

## 3. 背景与已知事实

用户希望把花饰设计与底托搭配放到网站；未来可接 Tripo3D，但先查可靠方法并形成 PRD。用户明确最终要 3D 打印、投入生产，并答复生产可能采用树脂打样与直接金属打印。最新补充：页面面向顾客，不展示无关信息/功能；提交后 AI 和人工分流，简单方案允许 AI 自动审批可做，不能自动确认或后续不可行时转设计师并通过邮件确定需求。

已有珠宝品牌将 AI 用作创意助手；可生产的用户定制系统通常同时依赖模板和规则。详见调研报告。由此提出的产品路线是本 PRD 的设计判断，不声称已完成自动制造验证。

| 已知 / 未知 | 当前状态及影响 |
|---|---|
| 网站产品资料 | 有 2D 图、BOM、54/57 mm 戒围；这些不能给出完整底托/连接的三维公差 |
| 可信 3D 装配资产 | 当前网站缓存未提供工厂签核的资产；须向原生模型负责人取得和验证 |
| 制造 profile | 工厂、机器、具体树脂/合金、壁厚、配合、公差与补偿尚未确认 |
| Tripo | 官方文档已转 API v3；官方公告 v2 于 2026-10-31 停用；本次未实际调用 |
| 材料及石色 | 只读已批准产品事实库；不从效果图或色名推断矿物/材料/库存 |
| 网站销售规则 | 现有可售戒围与库存逻辑不因共创变更；定制价格、交期与售后须另定，不能直接套现有商品 |

术语：此处「花饰」包含装饰模块、几何造型和浮雕等，不只指植物花朵。页面显示语言沿用网站 EN/FR；中文保留为需求与客服工作对照。

## 4. 目标与衡量

用户目标：把想法变成可理解的方案，看清与底托搭配的效果，知道下一步怎样得到样件和成品。

品牌目标：积累品牌自己的设计意图与真实反馈，提高可制造设计的筛选效率，形成有来源、有版本的工程交接。

### 4.1 试点目标

以下是拟定验收目标，不是当前已达成结果或行业基准：

- 内部试点完成前，至少一款批准底托、两种受控花饰模板完成源/接口建档；没有批准资产的底托不进入可打印列表。
- 对每条拟开放的工艺路线，至少有完整的工程检查、实际工厂软件回读和对应实物样件/首件证据。只验证一条时，只开放该条路线。
- 所有自动通过可做审核的方案，均有已签核的适用范围、对应输入/版本及检查证据；超范围、低置信度、资料不足和失败分流都交给设计师。
- 所有标记为「可打样」或「生产已确认」的版本，均能追溯到源、接口和工艺 profile。已验证模板范围内可按批准流程自动检查和放行；范围外补工程/实物验证。
- 提交回执、自动审核结果、转人工、补充资料及最终确认邮件可追溯、可回复；不把发送排队或发送失败标成已成功通知。
- 重复点击、刷新或回调重放不产生重复付费生成任务；建立可审计用量记录。
- 在试点周期统计完成率、保存/提交率、人工修订时间、首次可打样率、实际配合通过率与总成本，得到基线后再设增长目标。

不以图片好看、三角面数、AI 任务 success 或单次 STL 导出成功替代生产验收。

## 5. 用户与需求场景

| 人群 / 工作 | 需求 | 主要限制 |
|---|---|---|
| 已有 SUIJI 底托的用户 | 为自己的底托设计新花饰 | 必须选对实际型号/接口修订；不同底托不默认通用 |
| 首次购买者 | 先设计喜欢的花饰，再选匹配底托 | 需要看到包含物、颜色、比例、尺寸帮助与预计处理步骤 |
| 送礼者 | 表达主题、纪念日或收礼人喜好 | 不要求其懂建模；戒围和制造方案可后续确认 |
| 品牌设计/客服 | 从模糊描述整理可执行简报 | 需保留原意、修改点、版本与沟通状态 |
| 工程 / 工厂 | 把方案转成可制造工程，定义可复用的自动处理范围 | 真实接口、BOM、尺寸、公差、工艺、模板资格与追溯 |

## 6. 价值主张

面向消费者：从自己的喜好开始，几步看到与 SUIJI 底托搭配的设计；清楚区分灵感效果与已确认的制作方案。

面向设计和生产：可变造型放在批准的设计空间内，连接结构独立受控；每个可打印文件都有原生工程和检查记录，减少误配及反复返工。

SUIJI 的识别来自真实的钛部件、可换结构、自己的轮廓/纹理/石框和佩戴体验。页面沿用品牌白与冰蓝、清楚的排版与自有产品视图；不复制竞品的整套色彩、手绘元素与模块排列。

## 7. 解决方案

### 7.1 顾客端边界与主流程

**网站上的 AI 辅助设计功能面向顾客。** 页面只围绕「设计花饰、搭配底托、提交、查看审核进展、邮件沟通」展开。PRD、skill、API、模型供应商、工厂参数、检测面板、审核后台、用量和管理操作均留在内部，不成为顾客页面的模块、导航或按钮。

拟议入口：品牌的共创/设计栏目，以及适配产品页的「设计你的花饰」。URL 先与现有网站规划核对，暂记 `/pages/design-studio`；本次不创建路由或发布功能。

顾客主流程：**选择底托 → 描述/生成花饰 → 搭配和修改 → 填邮箱并提交 → 查看审核进展 → 收到结果或设计师邮件 → 确认需求及制作安排。**

| 页面区域 | 顾客可见内容 | 要求 |
|---|---|---|
| 简短介绍 | 用自己的想法设计可搭配 SUIJI 底托的花饰 | 一段介绍和开始按钮，不放研究报告、内部架构或功能大合集 |
| 设计工作区 | 实际底托、花饰方案、风格/轮廓/纹理/已核配色、参考图（可选） | 只显示对当前设计有效的选项；不要求顾客填写工厂公差、API 或文件参数 |
| 搭配预览 | 批准角度的主视、必要结构视图、切换方案、修改、重置视角 | 缺合格资产时清楚说明为意向预览；静态图遵守最终展示角度要求 |
| 提交设计 | 邮箱（必填）、需求备注；称呼可选，已有底托信息按需要提供 | 提交的是选定版本和需求；不在前端展示审核阈值或提供自己批准的按钮 |
| 提交后 | 设计编号、方案摘要、收件邮箱、简短状态、修改/补充入口 | 原方案保留；说明我们会先审核，需要进一步确认时由设计师邮件联系 |
| 审核与后续 | 可以制作 / 设计师确认中 / 请补充信息 / 待你确认 | 给有用的原因和下一步；不显示模型评分、工厂日志或内部任务错误 |

允许先找灵感后选底托；提交制作评估前必须确认具体底托或明确标为待设计师确认。主页面不塞入与本次设计无关的营销问卷、订阅、游戏、管理工具或后台功能。

提交后分流：

1. AI 审核设计和资料；对简单、在已验证工艺/结构范围内且必要检查通过的设计，**自动审批是否可做，无需每次再等设计师人工签核**。
2. AI 未通过、无法判断、信息不足、结构/工艺复杂、超出已验证范围，交设计师审核；不直接向顾客作最终拒绝。
3. AI 通过后，在工程/工艺/样件等后续环节发现不可行或不符合要求，也转交设计师重新确认，并通过邮件解释需要调整的内容。
4. 设计师通过邮件补充资料、沟通修改、确认需求及制作安排。简单自动通过的方案也发送结果邮件；价格和交期依实际已确认规则给出。

顾客看到的「可以制作」表示方案已通过制作可行性审核。打印文件和最终生产资格按工程及工艺记录管理；预览成功、AI 生成成功不自动等于审核通过。

### 7.4 允许修改的范围

优先试点：一款已批准底托，搭配两种受控花饰模板，例如外框/轮廓变化与浅浮雕表面。具体模板要由品牌和工程共同选定；不是以此重命名或改造现有 F01/F02。

用户可调：在模板允许范围内的轮廓、装饰节奏、真实可制造的纹理/浮雕和已核配色；有石款仅使用已批准石件及石座规格。UI 只显示对该款有效的选项。

受保护：连接孔/耳/轴/扣合面、局部基准与安装轴、真实 Logo/Ti 字形及位置、关键受力区域、石座配合、底托原生尺寸。现有规则中，连接环所在同一实体面朝内且 Logo/Ti 同面，逐款中线/接触与约 1 mm 最终相对高差均须继承原生批准证据；**这个 1 mm 目标不是制造公差，也不是所有款统一平移量。**

任意自由造型可以提交创意评估；未经工程化，不能出现在可打印/量产出口。纹理图片、凹凸贴图和金属颜色本身不会生成可打印浮雕，也不会决定实体材料或钛的表面颜色工艺。

### 7.5 审核分流与制造资格（内部规则）

三条状态独立记录，避免把生成成功当成审批，或把可做审批当成已完成制造：

| 状态轴 | 状态示例 | 决定依据 |
|---|---|---|
| 生成任务 | queued / running / success / failed / cancelled | 提供方任务及服务端核对 |
| 设计可做审核 | submitted → ai_review → auto_approved / designer_review → needs_info / feasibility_approved / revision_required | 有资格的 AI 审核或设计师决定 |
| 打印/生产资格 | not_evaluated → checks_passed → sample_or_qualification_review → approved / hold | 相应设计、模板覆盖范围、工艺与验收记录 |

#### AI 可以自动通过的条件

简单工艺/结构可以自动审批是否可做。系统内部须能识别并证明：对应底托接口已批准；花饰在预先签核模板/参数范围内；材料、工艺、关键尺寸及必要信息齐全；关键几何/装配/工艺硬检查通过；AI 判断处于经试点验证可自动处理的范围。

**允许范围由设计/工程与工厂预先批准，范围内的顾客设计按规则自动审批。** 不要求每一单重新人工审批。新模板、新接口、新材料/工艺或无法证明被覆盖的变化，先走设计师与相应资格验证。置信度/阈值由实际试点评测确定，不填一个通用百分数。

可做审核结果发送给顾客，后续报价/交期/制作安排按真实规则确认。自动审批和自动生产放行采用各自规则；已有模板和工艺资格可以在覆盖范围内复用，不能为任意新结构跳过制造验证。

#### 必须转设计师的情况

AI 未通过、低置信度、无法判断、资料缺失、复杂/新结构、新工艺、超出范围或硬检查失败，都进入 designer_review。AI 提供原设计、理由、失败位置和可行修改建议给设计师；顾客只看到有意义的状态与下一步，不看到内部评分与日志。

AI 自动通过后若发现不可行、关键数据错误、实际样件/后处理不达要求等，进入 designer_review_after_approval：冻结原通过结果继续驱动制作的权限；保留原始记录，不篡改历史；由设计师邮件解释、补充/修改并重新确认。不能静默继续生产，也不能把方案直接当作最终拒绝。

设计师可要求补充资料、修改方案、说明可行替代、确认可做。改动形成新版本；最终结果绑定该版本和工艺范围。顾客通过邮件确认修改/需求，后台记录对应沟通和确认，而不是替顾客默认同意。

#### 打印与生产出口

「可做样件」需要工程数据、该路线数字检查、导出回读及适用审批齐全；范围内可按批准流程自动检查，范围外由工程/设计师处理。

「生产已确认」需要该版本处在已验证制造范围内，且满足工艺和成品验收规定。对新/未覆盖结构补样件或首件验证；已验证模板可按覆盖范围复用证据。树脂和金属路线分别管理；AI 不得自行宣告某个未经确认的工艺/接口已获资格。

### 7.6 两条制造路线

| 项目 | A：树脂打样 | B：直接金属打印 |
|---|---|---|
| 目的 | 验证外形、比例、配合与装配方案 | 用选定金属及工厂工艺得到实际首饰部件 |
| 必备定义 | 机器、树脂/版本、层厚、朝向、支撑、清洗/后固化、测量阶段 | 工厂、具体合金、机器/工艺版本、层厚、支撑/取粉、热处理/后加工/抛光 |
| 尺寸处理 | 由该 profile 规定补偿和允许偏差 | 单独定义成形、后处理与最终接口尺寸；不得套树脂补偿 |
| 数字检查 | 壁厚/细节、闭合实体、排液/支撑、尺寸/装配 | 壁厚/筋孔、悬垂、封闭腔/取粉、支撑可达、变形及加工余量 |
| 实物检查 | 后处理后测量，与真实底托装配、必要佩戴体验 | 首件最终尺寸、连接功能、表面与结构验证；按工厂要求形成批次追溯 |
| 批准范围 | 仅相应样件和目的 | 仅对应版本、材料和工艺的生产范围 |

用户说两条都可能使用，因此后台须可分别建立两条记录；不是要求消费者先理解机器与工艺。若树脂样件之后转金属，保留前一阶段成果，但必须完成 B 的金属首件准入。将来决定树脂铸造时另加铸造 profile，不默认普通珠宝铸造适用于钛。

每个 profile 至少包含：修订与签核人、材料/机器、最小壁厚/细节/孔/间隙、关键尺寸及容差、支撑/排液或取粉、表面/后处理、补偿执行环节、接收软件和格式、数字/实物验收方法。未知值用 null/待确认，不填通用经验数值。详见已固定的[工厂资料模板](https://github.com/ywoffer2024-max/Suiji-Shopify/blob/0423248279eb5ec43bb280ab7dfba4ccff1d26ea/research/2026-10-31-ai-charm-prd-v0.1-7de2b129/factory-process-intake-v1.md)。

### 7.7 输出文件合同

| 文件 | 内容与限制 |
|---|---|
| `preview.glb` | 网页轻量展示；使用从批准工程派生的资产及明确单位转换，不承担制造资格 |
| 原生工程 | 真实可编辑源，如 3DM、FCStd、参数脚本或实际网格源；保存组件与建模来源 |
| `manufacturing.step`（适用时） | 当实际 CAD 工程可导出时提供；有曲面/实体的交换文件不一定带完整参数树，不将网格包装成精密 CAD |
| `part-*.stl` | 按 BOM 分件的成品设计几何；数值采用 mm，附尺寸说明和单位清单；不能混入展示用底托、石头代理或支撑 |
| `manufacturing.3mf` | 工厂接受时提供，显式毫米单位、对象与装配关系；核 actual exporter 支持内容，不默认有颜色/打印设置 |
| 工艺项目（按需） | 工厂认可的带支撑/切片工程及机器文件；与无支撑设计源分开，机器执行文件由工厂负责确认 |
| `dimensions.pdf/csv`、`bom.json` | 关键尺寸、测量基准、材料/分件、包含物、工艺 profile 与审核修订 |
| `validation.json`、交付说明 | 检查范围/结果、软件版本、导出参数、单位和源/文件哈希、未验项、批准范围与责任人 |

文件名为拟议结构，具体按工厂接收规则调整。STL/3MF 是模型交换文件，不等于机器可直接运行的作业。首版提供的下载分为「设计预览」「样件包」「生产包」，权限随状态与版权/商业政策决定；默认工厂/后台工程人员取得制造包，消费者是否可下载另行确定。

导出后必须在另一个读取环节重新打开：查 mm 单位、实际包围尺寸、关键配合尺寸、分件数量及预期实体；核曲面离散误差对关键尺寸的影响。不能先让全体网格缩放为某个包围盒，再声称真实接口精确。

### 7.8 技术结构（内部）

建议结构：顾客专用 Shopify 页面与轻量预览组件 → 独立服务端 → 私有任务/设计存储 → 候选生成与 CAD 检查 → AI 审核分流 → 自动可做审批或设计师审核 → 邮件沟通/确认 → 制造交付。设计师工作区、工厂资料及管理端独立鉴权，不嵌入顾客界面。任务不能依赖页面保持打开；Shopify 主题内不得放 Tripo key，也不把耗时建模放在同步请求内等待。

Tripo 适配按官方 API v3；图片/多视图只作为候选几何来源。生成、单位设定、接口装配、工程修订和导出都保留版本关系。关键连接不交给 AI 重画；需要时将装饰外形工程化后再与真实组件连接。

自动 CAD 的首版选择原则：优先现有已验证原生管线；受控模板可评估 Rhino/参数化 CAD 或 CadQuery/FreeCAD。自由曲面可保留经检测网格；不为使用某个 skill 迁移全部工程或重装已验证环境。生产计算实施遵循现有唯一 owner、T7 与独立审查规则。

API 约定：

- 依据账户实际地区固定 endpoint；锁 SDK、模型、选项及生成输入。API v3 与模型版本分别记录。
- 提交前保存本地任务与去重键，成功收到提供方 ID 立即持久化；POST 超时后先查已知任务/人工恢复，不能盲目再付费创建。
- 回调验签、去重，快速确认接收后异步处理；回调缺失可有界查询。只查询不重新创建。
- API key、webhook secret 和邮件凭据只在服务端批准的凭据系统；不进浏览器、Git、PRD 或日志。下载存储地址不附带 API 凭据。
- 输出下载校验大小、类型和哈希，转入项目受控存储；供应商临时链接不作为永久设计档案。
- 客户图片与设计默认私有。记录权利确认、最小必要联系信息、访问权限和删除/保留政策；实施前与 T7 不删规则协调，客户可删除数据不应落入不可删除的历史生产档案。
- 设置每用户/会话/日的待定额度、并发与成本上限；在免费/付费政策确定前只开放内部试点，不创建无限公开付费入口。
- 检测失败后只做有记录、可限定区域的修订；最多两次未改善的同一假设后转人工工程判断，不自动无限重生成。

邮件与审核服务（内部）：

- 提交成功保存设计与邮箱后发回执；审核结果、转人工、补充资料和修改确认各有对应邮件事件。
- contact@suijijewelry.com 作为顾客服务发件/回复身份；实际 Sender/域认证与收信需部署前验证。目前只完成网站公开联系邮箱更新，未宣称该邮件链路已开通。
- 邮件使用设计编号、版本、所需动作及顾客可访问的设计链接；不附内部工厂参数、审核评分、供应商链接或 API 信息。
- 自动可做通过可自动发结果；转人工建立设计师待办并通知顾客，设计师在同一设计/邮件链里明确问题、方案与需求。
- 队列及 event_id 去重，记录发送/接受/退信；发送失败可有界重试并留内部待办，不重复创建设计或重复发送确认。发送排队不等于顾客已收到。
- 顾客回复关联正确设计和版本；改收件地址需验证归属；服务邮件与营销订阅分开。此轮不发实际邮件或更改账户/DNS。

官方契约来源：[概述](https://developers.tripo3d.ai/en/docs/introduction)、[SDK](https://developers.tripo3d.com/en/docs/sdk)、[转换](https://developers.tripo3d.com/en/docs/models-convert)、[回调](https://developers.tripo3d.com/en/docs/webhooks)。文档对 3MF 颜色有冲突，须在接入测试核实；本 PRD 不依赖该颜色承诺。

### 7.10 有意义的验收场景

| 编号 | 场景 | 应看到的结果 |
|---|---|---|
| T01 | 用户刷新、返回和重复点击生成 | 找回同一任务；不会重复扣费创建 |
| T02 | 提供方超时但任务可能已创建 | 保留 pending/reconcile，恢复查询；不自动再 POST |
| T03 | 假回调或回调重复 | 不改变审批状态；合法回调只更新一次，且不能直接发布生产包 |
| T04 | 没有批准接口或工艺字段为空 | 可保存/提交意图；转设计师，AI 不自动通过，制造出口保持待确认 |
| T05 | 生成花饰侵入连接核心，或改变内外面 | 结构门阻断，不能靠转相机/隐藏部件通过 |
| T06 | 已批准组件导出/重开 | 名义尺寸、局部几何/朝向及装配轴一致；偏差按 profile 判定 |
| T07 | mm/m 混淆、STL 导入错误尺寸 | 单位和尺寸回读识别并阻断，不默默自动缩放 |
| T08 | 孤立片、错误开口、自交、不可接受薄壁/细孔 | 数字检测给出位置和原因，不能只修文件外观 |
| T09 | 石头、框、底托代理混在一个打印网格 | 按 BOM 检出；成品分件与设计/支撑文件正确 |
| T10 | 树脂样件已通过，选择金属路线 | 保留树脂记录；金属须重新做该 profile 与首件验收 |
| T11 | 后加工/抛光导致最终配合失效 | 以最终测量和装配判定，不能拿打印前尺寸替代 |
| T12 | 生产已确认后改外形、接口、材料或工艺 | 新版本形成影响评估及必要复核；旧包批准不自动继承 |
| T13 | 手机不支持 WebGL / 使用键盘 | 批准角度静态图、选项和保存流程仍可用；错误/状态 EN/FR 一致 |
| T14 | 工厂软件打开最终 STL/3MF | 单位、尺寸、分件/实体和所需工艺设置逐项回读；未验项明确 |
| T15 | 新/超范围样件或首件实物装配 | 与真实底托核比例/接触/活动/保持及表面，记录证据；覆盖范围内才可复用模板资格 |
| T16 | 简单、在已验证范围且检查全通过 | AI 直接给可做审批，自动发结果，无每单强制人工等待 |
| T17 | AI 未通过/不确定/复杂/资料不足 | 建设计师待办和邮件链；不直接最终拒单 |
| T18 | AI 通过后发现不可做或后续验证失败 | 冻结继续制作，转设计师、邮件说明并重新确认版本 |
| T19 | 顾客界面及顾客邮件 | 只出现设计/搭配/提交/状态/相关帮助；没有 skill、API、工厂或管理功能 |
| T20 | 提交邮箱缺失/格式错误 | 指出该字段问题，保留方案；不显示已完成可联系的提交 |
| T21 | 重复回调/重复发送/邮件退信 | 同事件只通知一次；失败记录和内部待办，不伪称送达 |
| T22 | 顾客回复补充、修改或确认 | 关联正确设计/版本，修改触发受影响范围重审，确认留记录 |

这些是后续开发/试点的验收要求。本轮尚未执行模型、打印或 API 集成测试。

### 7.11 假设与风险

- 假设：有至少一款原生底托/接口能够完成批准；若没有，先由原生负责人补齐，不以 AI 反推。
- 假设：工厂可提供至少一种路线的接收标准；未知壁厚/公差不得由网站自行设置。
- 待验证：Tripo 对小尺度花饰细节的可用性、修订耗时及成本；通过相同输入、真实目标尺寸的有界对比试验判断，不承诺一次生成成功。
- 待验证：用户是否愿意为定制提交信息/等候样件；先用真实完成和样件反馈评估，不把生成次数当需求成立。
- 内容风险：AI 材质、证书、石种、重量与效果可能虚构；事实只由批准材料库与工程测量提供。
- 生产风险：成形方向、支撑、抛光/加工、活动连接对结果有影响；轮廓看起来相同不能覆盖相应工艺复核。
- 隐私与资源：用户上传图片不能进入公开 Git；配额、存储和产物白名单须先就绪，再开放实际生成。

### 7.12 本版新增的顾客端与审核边界

本 PRD 中的技术、案例与审核政策供内部实施；实际网站页面聚焦顾客的设计任务。顾客提出想法后，AI 自动审批简单可做方案，设计师接管复杂/无法通过及通过后发现问题的方案，并通过邮件沟通确定需求。
