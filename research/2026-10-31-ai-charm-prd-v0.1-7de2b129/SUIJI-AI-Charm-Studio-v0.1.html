SUIJI：AI 辅助花饰设计与可打印生产方法调研

版本 v1 · 调研核验日 2026-10-31 · 对象：SUIJI 网站、设计及生产负责人

判断与建议

已有珠宝品牌把 AI 用于创意探索、变体与客户沟通，也已有可定制、实际 3D 打印的首饰系统。本次没有找到足够公开证据，能证明一个现成 skill 可将任意提示词直接变成尺寸准确、适配 SUIJI 底托并已通过钛首饰量产验证的文件。 这是本次证据范围的结论，不是声称市场上不存在相关技术。

适合 SUIJI 的方法是：用户意图 → 有边界的花饰造型 → 锁定真实接口的 CAD 工程化 → 工艺检查 → 实物验证 → 打印及生产交付。 AI 与 Tripo 提供创意和候选几何；经过核定的 CAD、工艺参数和实物测试共同保证制造要求。

用户最新指示：最终必须能 3D 打印、用于生产；可能采用「树脂打样」和「直接钛等金属打印」两条路线。因此两条路线应分别保留资格、文件和验证记录；树脂样件通过后，金属制造仍须独立首件确认。

从可看模型到生产文件

建议保留三种交付层次：网页 GLB 负责预览；可编辑 CAD/工程源负责尺寸、接口和修订；STL/3MF 负责工厂认可的打印交换。STL 不携带明确单位，应以 mm 为本项目合同单位并附尺寸核验。3MF 标准支持显式单位，默认毫米；文件仍须在实际工厂软件重新打开验证。格式支持不等于机器已准备执行。3MF 官方规范、Prusa 官方导入格式

路线先做什么放行凭据
树脂打样选定打印机/树脂/层厚/后处理；核轮廓、接口和装配，清楚说明样件用途已核 STL/3MF、切片回读、实际样件测量与佩戴/装配评审
直接金属打印选定工厂、具体合金、机器和工艺；核支撑、取粉、变形、表面处理与配合面加工金属工艺 profile、工厂 DFM、首件实测与功能验证，批准后才正式生产

树脂打样可用于外形/配合验证；不同树脂和后处理并不等同最终金属性能。将来若决定铸造，要另建铸造工艺，不从「树脂样件」自动推导钛能按普通珠宝铸造路线生产。Formlabs 官方也把样件、可铸造材料和最终功能件的用途分开，具体设计要求依材料而异。Formlabs 材料用途与流程

首版不写一个适用于所有机器/材料的最小壁厚或统一公差。工厂须给定关键尺寸及测量方法、打印和抛光/加工后的允许偏差；未知字段保持待确认，生产出口保持关闭。模型检查、工厂软件回读和实物验证缺一不可。

PRD — SUIJI AI 花饰共创与底托搭配

版本：v0.1 · 2026-10-31 · 状态：需求初稿，供网站、原生建模及工厂共同评审

关联文档：方法与案例调研、Skill 审查、工厂资料模板。

1. 概要

在 SUIJI 网站增加花饰共创页面，让用户用文字、参考图和可选项表达想法，生成设计方案，再与真实底托搭配预览。最终目标是可准确制作的首饰：通过 CAD、工艺与实物验证后，交付工厂认可的 STL/3MF 打印文件及工程资料。

首版把可变花饰和不可随意变化的底托接口分开管理。支持准备「树脂打样」及「直接金属打印」两条工艺路线，分别判定可打印与可生产状态。

3. 背景与已知事实

用户希望把花饰设计与底托搭配放到网站；未来可接 Tripo3D，但先查可靠方法并形成 PRD。用户明确最终要 3D 打印、投入生产，并答复生产可能采用树脂打样与直接金属打印。

已有珠宝品牌将 AI 用作创意助手；可生产的用户定制系统通常同时依赖模板和规则。详见调研报告。由此提出的产品路线是本 PRD 的设计判断，不声称已完成自动制造验证。

术语：此处「花饰」包含装饰模块、几何造型和浮雕等，不只指植物花朵。页面显示语言沿用网站 EN/FR；中文保留为需求与客服工作对照。

4. 目标与衡量

用户目标：把想法变成可理解的方案，看清与底托搭配的效果，知道下一步怎样得到样件和成品。

品牌目标：积累品牌自己的设计意图与真实反馈，提高可制造设计的筛选效率，形成有来源、有版本的工程交接。

4.1 试点目标

以下是拟定验收目标，不是当前已达成结果或行业基准：

  • 内部试点完成前，至少一款批准底托、两种受控花饰模板完成源/接口建档；没有批准资产的底托不进入可打印列表。
  • 对每条拟开放的工艺路线，至少有完整的工程检查、实际工厂软件回读和对应实物样件/首件证据。只验证一条时，只开放该条路线。
  • 所有标记为「可打样」或「生产已确认」的版本，均能追溯到源、接口和工艺 profile；缺任何必需字段则不能放行。
  • 重复点击、刷新或回调重放不产生重复付费生成任务；建立可审计用量记录。
  • 在试点周期统计完成率、保存/提交率、人工修订时间、首次可打样率、实际配合通过率与总成本，得到基线后再设增长目标。

不以图片好看、三角面数、AI 任务 success 或单次 STL 导出成功替代生产验收。

送礼者表达主题、纪念日或收礼人喜好不要求其懂建模；戒围和制造方案可后续确认
品牌设计/客服从模糊描述整理可执行简报需保留原意、修改点、版本与沟通状态
工程 / 工厂将方案转成可制造、可复用工程必须有真实接口、BOM、尺寸、公差、工艺和审批

6. 价值主张

面向消费者：从自己的喜好开始，几步看到与 SUIJI 底托搭配的设计；清楚区分灵感效果与已确认的制作方案。

面向设计和生产：可变造型放在批准的设计空间内，连接结构独立受控；每个可打印文件都有原生工程和检查记录，减少误配及反复返工。

SUIJI 的识别来自真实的钛部件、可换结构、自己的轮廓/纹理/石框和佩戴体验。页面沿用品牌白与冰蓝、清楚的排版与自有产品视图；不复制竞品的整套色彩、手绘元素与模块排列。

7.1 进入页面与主流程

7.4 允许修改的范围

优先试点：一款已批准底托，搭配两种受控花饰模板，例如外框/轮廓变化与浅浮雕表面。具体模板要由品牌和工程共同选定；不是以此重命名或改造现有 F01/F02。

用户可调：在模板允许范围内的轮廓、装饰节奏、真实可制造的纹理/浮雕和已核配色；有石款仅使用已批准石件及石座规格。UI 只显示对该款有效的选项。

受保护：连接孔/耳/轴/扣合面、局部基准与安装轴、真实 Logo/Ti 字形及位置、关键受力区域、石座配合、底托原生尺寸。现有规则中，连接环所在同一实体面朝内且 Logo/Ti 同面，逐款中线/接触与约 1 mm 最终相对高差均须继承原生批准证据；这个 1 mm 目标不是制造公差，也不是所有款统一平移量。

任意自由造型可以提交创意评估；未经工程化，不能出现在可打印/量产出口。纹理图片、凹凸贴图和金属颜色本身不会生成可打印浮雕，也不会决定实体材料或钛的表面颜色工艺。

7.5 模型、工程和生产状态

采用三条相互关联但独立的状态：

状态轴例子谁决定
AI 任务queued → running → success / failed / cancelled提供方任务与服务端核对
设计版本concept → engineering_candidate → engineering_reviewed设计/工程审核
工艺资格not_evaluated → checks_passed → sample_review → approved / hold特定工艺 profile 的检查、实物与工厂签核

「可做样件」要求：工程版本完整、该路线工艺数据齐全、数字检查通过、导出与工厂软件回读完成、工程负责人批准发出样件文件。

「生产已确认」要求：该版本/路线实际首件或样件完成所需验证、工厂及品牌签核；不是 AI 对其自身输出打分。材料、机器/工艺参数、接口或源几何变化时，按变更影响重新核准，不能沿用不相关批准。

失败/未知项保持 HOLD 并给具体理由，如「底托接口未确认」「薄壁不符合选定工艺」「抛光后配合尺寸待核」。AI 返回失败不抹掉已保存方案；工艺未知不阻止继续整理创意简报。

项目A：树脂打样B：直接金属打印
目的验证外形、比例、配合与装配方案用选定金属及工厂工艺得到实际首饰部件
必备定义机器、树脂/版本、层厚、朝向、支撑、清洗/后固化、测量阶段工厂、具体合金、机器/工艺版本、层厚、支撑/取粉、热处理/后加工/抛光
尺寸处理由该 profile 规定补偿和允许偏差单独定义成形、后处理与最终接口尺寸；不得套树脂补偿
数字检查壁厚/细节、闭合实体、排液/支撑、尺寸/装配壁厚/筋孔、悬垂、封闭腔/取粉、支撑可达、变形及加工余量
实物检查后处理后测量，与真实底托装配、必要佩戴体验首件最终尺寸、连接功能、表面与结构验证；按工厂要求形成批次追溯
批准范围仅相应样件和目的仅对应版本、材料和工艺的生产范围

用户说两条都可能使用，因此后台须可分别建立两条记录；不是要求消费者先理解机器与工艺。若树脂样件之后转金属，保留前一阶段成果，但必须完成 B 的金属首件准入。将来决定树脂铸造时另加铸造 profile，不默认普通珠宝铸造适用于钛。

每个 profile 至少包含：修订与签核人、材料/机器、最小壁厚/细节/孔/间隙、关键尺寸及容差、支撑/排液或取粉、表面/后处理、补偿执行环节、接收软件和格式、数字/实物验收方法。未知值用 null/待确认，不填通用经验数值。详见工厂模板。

导出后必须在另一个读取环节重新打开：查 mm 单位、实际包围尺寸、关键配合尺寸、分件数量及预期实体；核曲面离散误差对关键尺寸的影响。不能先让全体网格缩放为某个包围盒，再声称真实接口精确。

7.8 技术结构（内部）

建议结构：Shopify 页面与轻量预览组件 → 独立服务端 → 任务数据库/私有对象存储 → AI 图像/Tripo 候选生成 → CAD 与检测 worker → 审核与制造交付。任务不能依赖页面保持打开；Shopify 主题内不得放 Tripo key，也不把耗时建模放在同步请求内等待。

Tripo 适配按官方 API v3；图片/多视图只作为候选几何来源。生成、单位设定、接口装配、工程修订和导出都保留版本关系。关键连接不交给 AI 重画；需要时将装饰外形工程化后再与真实组件连接。

自动 CAD 的首版选择原则：优先现有已验证原生管线；受控模板可评估 Rhino/参数化 CAD 或 CadQuery/FreeCAD。自由曲面可保留经检测网格；不为使用某个 skill 迁移全部工程或重装已验证环境。生产计算实施遵循现有唯一 owner、T7 与独立审查规则。

API 约定：

  • 依据账户实际地区固定 endpoint；锁 SDK、模型、选项及生成输入。API v3 与模型版本分别记录。
  • 提交前保存本地任务与去重键，成功收到提供方 ID 立即持久化；POST 超时后先查已知任务/人工恢复，不能盲目再付费创建。
  • 回调验签、去重，快速确认接收后异步处理；回调缺失可有界查询。只查询不重新创建。
  • API key、webhook secret 和邮件凭据只在服务端批准的凭据系统；不进浏览器、Git、PRD 或日志。下载存储地址不附带 API 凭据。
  • 输出下载校验大小、类型和哈希，转入项目受控存储；供应商临时链接不作为永久设计档案。
  • 客户图片与设计默认私有。记录权利确认、最小必要联系信息、访问权限和删除/保留政策；实施前与 T7 不删规则协调，客户可删除数据不应落入不可删除的历史生产档案。
  • 设置每用户/会话/日的待定额度、并发与成本上限；在免费/付费政策确定前只开放内部试点，不创建无限公开付费入口。
  • 检测失败后只做有记录、可限定区域的修订；最多两次未改善的同一假设后转人工工程判断，不自动无限重生成。

官方契约来源：概述、SDK、转换、回调。文档对 3MF 颜色有冲突，须在接入测试核实；本 PRD 不依赖该颜色承诺。

7.11 假设与风险

  • 假设：有至少一款原生底托/接口能够完成批准；若没有，先由原生负责人补齐，不以 AI 反推。
  • 假设：工厂可提供至少一种路线的接收标准；未知壁厚/公差不得由网站自行设置。
  • 待验证：Tripo 对小尺度花饰细节的可用性、修订耗时及成本；通过相同输入、真实目标尺寸的有界对比试验判断，不承诺一次生成成功。
